# YBM Podcast Transcripts

Baca dalam [Bahasa Melayu](README.ms.md).

Transcripts of Rafizi Ramli's long-form podcast (*Yang Bakar Menteri* / *Yang Berhenti Menteri* / *YBM*), built with the [same structured-archive approach](https://github.com/ChatPRD/lennys-podcast-transcripts) as Lenny's Podcast Transcripts.

Source playlist: https://www.youtube.com/playlist?list=PLqJKhYZQ8r9Uz3IPEh0lXpF17w3LQK62N

Only full episodes (1+ hour) are included. Short teasers, clip highlights, quote-card snippets, and shorter-format episodes from the same playlist are excluded.

> Transcripts and rewrites are generated by an AI model, not manually verified against the source recording. See [Accuracy note](#accuracy-note) before citing anything here.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the full pipeline diagram, the models evaluated along the way, and why the stack looks the way it does.

## Why this exists

Rafizi Ramli's podcast covers how specific government reforms got proposed, who blocked them, why, and what he'd do differently next time: detail that usually only exists inside a 2-3 hour video nobody has time to scrub through. I built this to put that record into text instead; a journalist can cite it, a biographer can quote it, and anyone trying to understand why a specific reform failed can search for it instead of scrubbing through hours of video.

## Structure

```
episodes/
├── yang-bakar-menteri/                  # 2024 run, 6 episodes
│   └── 2024-01-08-ep01-.../
│       ├── raw.md                       # close-to-verbatim transcript
│       ├── interview.md                 # polished Q&A rewrite, mixed language
│       ├── interview-en.md              # English translation
│       └── interview-ms.md              # Bahasa Melayu translation
└── yang-berhenti-menteri/               # 2025 rename onward, 61 episodes
    └── 2025-09-12-ep13-.../             # same 4 files per episode
data/
└── manifest.json                        # episode index (metadata only, no transcript text)
scripts/                                 # pipeline code, see ARCHITECTURE.md
ARCHITECTURE.md                          # the stack: setup, commands, verification
QA_CHECKLIST.md                          # generated by scripts/qa_check.py
```

Each episode lives in `episodes/<show-name>/<publish-date>-<title-slug>/` with four files. `<show-name>` is `yang-bakar-menteri` for the show's original 2024 run, or `yang-berhenti-menteri` for everything since the 2025 rename:

- `raw.md`: a close-to-verbatim transcript straight from the audio, with timestamps and speaker labels. Filler words are lightly cleaned up but nothing is paraphrased or summarized. Episodes transcribed by the local ASR fallback get their speaker labels from a separate acoustic diarization pass, not from the transcription model itself (see [ARCHITECTURE.md](ARCHITECTURE.md)).
- `interview.md`: a polished newspaper-style Q&A rewrite, kept in the original mixed English/Bahasa Melayu, closest to how the conversation was actually spoken.
- `interview-en.md`: the same rewrite, fully translated into English.
- `interview-ms.md`: the same rewrite, fully translated into Bahasa Melayu.

All four files share the same YAML frontmatter (title, video ID, YouTube URL, publish date, duration, view count, hosts, guests); the three interview versions also carry an AI-generated summary and topic tags. Pick whichever version suits your use case.

`data/manifest.json` is the full episode index (metadata only, no transcript text) used to drive the pipeline.

## Accuracy note

Transcripts and rewrites are generated by an AI model listening directly to the source audio. They are not manually verified against the original recording. Code-switching between Bahasa Melayu and English is preserved rather than translated, but errors, mishearings, or misattributed speaker turns are possible, especially in cross-talk. Treat `raw.md` as the closer-to-source reference and `interview.md` as an editorial rewrite built on top of it.

Episodes transcribed via the local ASR fallback (see [ARCHITECTURE.md](ARCHITECTURE.md#known-limitations)) get their `raw.md` speaker labels from a separate acoustic diarization pass (pyannote.audio) rather than from Gemini's own diarization. These start out as anonymous "Speaker N" labels that get manually mapped to real names during review, the same as Gemini's generic labels do. Treat any not-yet-reviewed episode's labels as unverified, particularly in fast multi-speaker exchanges.

`python scripts/qa_check.py` audits every episode for known failure signatures (truncated rewrites, hallucinated timestamps, leaked model reasoning, content dropped from the middle of an episode, and more) and writes the results to `QA_CHECKLIST.md`. Run it after any batch and check the output before trusting a clean exit code: several of these failure modes produce no error and no non-zero exit, only corrupted or truncated file content. A clean row means no *known* failure signature fired, not that the episode is verified -- two episodes read as clean for months while missing 41% and 80% of their content, until checks for those signatures were added.

Proper nouns (names, unusual spellings) transcribed by the local ASR engine aren't checked against a reference dictionary yet. A manual correction pass is planned, checking flagged words against Dewan Bahasa dan Pustaka's PRPM dictionary via the `malaya` library (see [ARCHITECTURE.md](ARCHITECTURE.md#known-limitations) for the tooling).
