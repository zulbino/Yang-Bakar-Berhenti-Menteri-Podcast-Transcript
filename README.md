# YBM Podcast Transcripts

Baca dalam [Bahasa Melayu](README.ms.md).

Transcripts of Rafizi Ramli's long-form podcast (*Yang Bakar Menteri* / *Yang Berhenti Menteri* / *YBM*), built with the [same structured-archive approach](https://github.com/ChatPRD/lennys-podcast-transcripts) as Lenny's Podcast Transcripts.

Source playlist: https://www.youtube.com/playlist?list=PLqJKhYZQ8r9Uz3IPEh0lXpF17w3LQK62N

Only full episodes (1+ hour) are included. Short teasers, clip highlights, quote-card snippets, and shorter-format episodes from the same playlist are excluded.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the full pipeline diagram, the models evaluated along the way, and why the stack looks the way it does.

## Structure

Each episode lives in `episodes/<publish-date>-<title-slug>/` with four files:

- `raw.md` -- a close-to-verbatim transcript straight from the audio, with timestamps. Filler words are lightly cleaned up but nothing is paraphrased or summarized. Most episodes have speaker labels; episodes transcribed by the local ASR fallback don't (see [ARCHITECTURE.md](ARCHITECTURE.md)).
- `interview.md` -- a polished newspaper-style Q&A rewrite, kept in the original mixed English/Bahasa Melayu -- closest to how the conversation was actually spoken.
- `interview-en.md` -- the same rewrite, fully translated into English.
- `interview-ms.md` -- the same rewrite, fully translated into Bahasa Melayu.

All four files share the same YAML frontmatter (title, video ID, YouTube URL, publish date, duration, view count, hosts, guests); the three interview versions also carry an AI-generated summary and topic tags. Pick whichever version suits your use case.

`data/manifest.json` is the full episode index (metadata only, no transcript text) used to drive the pipeline.

## Accuracy note

Transcripts and rewrites are generated by an AI model listening directly to the source audio. They are not manually verified against the original recording. Code-switching between Bahasa Melayu and English is preserved rather than translated, but errors, mishearings, or misattributed speaker turns are possible, especially in cross-talk. Treat `raw.md` as the closer-to-source reference and `interview.md` as an editorial rewrite built on top of it.

`python scripts/qa_check.py` audits every episode for known failure signatures (truncated rewrites, hallucinated timestamps, leaked model reasoning, and more) and writes the results to `QA_CHECKLIST.md`. Run it after any batch and check the output before trusting a clean exit code -- several of these failure modes produce no error and no non-zero exit, only corrupted or truncated file content.

## Pipeline

Requires a `GEMINI_API_KEY` environment variable, Python 3, Node.js, and ffmpeg. Two fallbacks cover the cases where Gemini isn't available or can't handle a call (see [ARCHITECTURE.md](ARCHITECTURE.md) for when and why): a local ASR model for the raw transcription stage, and the `claude` CLI for the rewrite stage.

Each episode's audio is downloaded from YouTube, uploaded to Gemini as a standalone audio file, and transcribed in a single pass -- comfortably within Gemini's 65k-token output limit even for the longest (~3.5hr) episode. The raw transcript then goes through separate rewrite/translation passes (mixed, English, Malay) as plain text. Referencing a YouTube URL directly (instead of downloading first) was tried and abandoned: Gemini loads the entire video at a much higher per-second token rate regardless of any offset given, which blows the 1,048,576-token input limit for anything beyond about an hour.

### One-time setup

YouTube blocks most `yt-dlp` client/format combinations behind PO tokens, SABR-only streaming, or DRM. The working combination: the `web_embedded` client, a locally-run PO-token server, and Node.js for JS challenge solving.

```bash
pip install -r requirements.txt

# Build the PO token server once
git clone https://github.com/Brainicism/bgutil-ytdlp-pot-provider ~/bgutil-ytdlp-pot-provider
cd ~/bgutil-ytdlp-pot-provider/server && npm ci && npx tsc

# ffmpeg is required to remux yt-dlp's raw DASH audio fragments into a valid
# container -- without it, Gemini's Files API rejects the upload outright.
winget install Gyan.FFmpeg
```

`scripts/yt_download.py` starts the PO token server automatically if it isn't already running, and passes `--ffmpeg-location` explicitly (falls back to the winget install path if `ffmpeg` isn't on `PATH`).

Uploads must also force the mime type to `audio/mp4` -- the SDK auto-detects `.m4a` files as `video/m4a`, which Gemini's backend silently fails to process (no video track). `scripts/lib_gemini.py`'s `upload_audio()` handles this.

### Running

```bash
# Refresh the episode manifest from the playlist (only episodes >= 1 hour)
python scripts/build_manifest.py

# Process one episode
python scripts/transcribe_episode.py <video_id>

# Process everything not yet done, oldest episode first (or pass specific video IDs)
python scripts/batch_process.py

# Same, but raw transcription via local ASR instead of Gemini (see ARCHITECTURE.md)
python scripts/batch_process.py --engine local

# Same, but the rewrite/translate/metadata stage via the claude CLI instead of Gemini
python scripts/batch_process.py --rewrite-engine claude

# Audit every episode for known failure signatures, writes QA_CHECKLIST.md
python scripts/qa_check.py
```
